# 腰牌本地启动不依赖旧语音终端配网

## 依据

首版目标要求腰牌在手机离线后仍能完成游戏，后台消息由手机经蓝牙转发。ESP32-S3 不需要自行连接模型服务，也不应因为缺少 Wi-Fi 配置而停留在配网页面。

第一次实机启动中，参考语音终端的自动配网热点与音频、显示、蓝牙同时启动。日志出现内部内存不足、屏幕 SPI 传输失败及 LVGL 刷新等待中的看门狗告警，且未进入游戏首页。此事实推翻了“只要提前启动蓝牙，旧终端启动流程便足以承载离线游戏”的假设。

## 决定

`esp32s3-chat-badge` 板型启动屏幕、音频服务、主事件任务及活动蓝牙服务后，结束旧语音应用的网络启动流程。不自动开启配网热点、音频配网、旧远程协议或远程升级，也不启动旧语音状态栏时钟任务。其他板型维持原启动流程。

音频服务仍保留，未以删除扬声器能力规避问题。原设置代码保留，但主动配网不是本首版闭环的依赖；后续若需要新增腰牌直连联网能力，必须重新验证内存预算与界面任务边界，不能直接恢复自动配网。

## 验证边界

通过同一实机启动脚本比较修复前后日志；检查游戏首页、蓝牙广播与内存／刷新／看门狗错误。该检查不替代触摸操作、授权回执、收藏重启保持或三十分钟完整流程验收。
