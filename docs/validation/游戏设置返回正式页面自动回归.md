# 游戏设置返回正式页面自动回归

2026年10月3日，补充用户“进入设置后返回不能丢游戏”的快速自动证据。不改当前固件、不重新烧录、不清进度，不替代实物设置专项录像。

## 检查入口与范围

`bash scripts/test-qin-render.sh` 现在依次运行既有图片／轮廓检查和 `qin_page_test`。后者编译正式 `pg_exploration.c`、实际LVGL、正式中文字体、四张生产素材及游戏状态逻辑；通过页面生命周期加载并发送实际按钮和滑块事件，不复制设置返回逻辑。

设备状态、亮度／音量保存接口和页面管理器配置仅在宿主检查中使用边界替身；不访问NVS、串口、真实扬声器或用户收藏。测试起点使用游戏逻辑放置一片，不冒充触摸拖放。字体、图片和页面实际进入360×360缓冲绘制，但不模拟圆屏遮挡或手指尺寸。

## 独立预期与结果

- 点击“开始秦俑归阵”只调用一次开始游戏。
- 带着一片已放置碎片进入设置；亮度范围10—100，音量范围0—100。
- 改变滑块值不立即保存；发出松手事件后，亮度17与音量0分别保存一次。
- 点击“返回”后仍显示游戏，开始游戏调用次数仍为一次，碎片掩码、当前选择、连续错误次数保持；正式槽对象包含图片并维持金色四像素边框。
- 退出到首页，再进设置返回，仍回首页，不误进游戏，不再次调用开始游戏。
- 固件配置、正式素材和字体共同绘制成功；保留四图与876个亮边变化像素的既有检查。

上述检查通过，日志 `logs/qin-page-settings-test.log`。测试显式启用断言，构建模式变化不会把断言静默关闭。

负向验证：临时令正式 `close_settings` 错误地调用 `exploration_begin`，回归在“调用次数与碎片状态保持”断言处失败，退出码134。随后撤回临时修改并重新通过全部检查；生产文件没有该错误，未构建或烧录错误固件。失败日志 `logs/qin-page-settings-negative.log`。这证明检查能捕获“返回后重开并丢碎片”，不是只检查源码文本。

## 结论

正式页面自动回归确认设置返回与松手保存行为，未新增固件功能或修改实物状态。仍需实物视频确认真实触控、亮度效果、音量与碎片视觉；自动回归不是用户已取消的三轮／三十分钟验收，也不能冒充已录制真实操作视频。
