# 长安游迹终端到访接口

## 范围与运行

本仓库提供后台接口，不实现或部署 K230 的摄像头、驱动、扫码和屏幕程序。当前会话固定为 `demo-001`，终端固定为 `k230-001`。工作人员网页、设备通信和地图查询仍在后续开发中，本文只列已经实现的接口。

开发依赖用 `uv sync` 安装。设置不同的 `CHANGAN_OPERATOR_TOKEN` 和 `CHANGAN_TERMINAL_TOKEN` 后，通过 `bash scripts/backend.sh` 前台运行；停止使用终端中断。日志位于 `logs/backend.log`，数据库默认为 `data/changan.sqlite3`。令牌不得提交到 Git。默认仅监听 `127.0.0.1:8000`；手机接入前必须配置 HTTPS，不应将开发服务直接公开。

`/health` 不要求令牌。其他接口要求 `Authorization: Bearer <令牌>`。工作人员令牌不能上报终端事件，终端令牌不能登记设备或解锁。服务启动时拒绝空令牌及相同令牌。开发用交互说明位于 `/docs`，机器可读契约位于 `/openapi.json`。

## 身份与地点

工作人员通过 `POST /api/v1/badges` 登记 `badge_id`、`display_number`、`device_id`。二维码只携带不透明腰牌标识；对接方将识别出的标识放入 `badge_id`，不得从二维码推定实物设备身份或地点。最终二维码文本封装格式待与对接方确定，本接口不依赖特定封装。

地点配置由终端调用 `GET /api/v1/terminal/configuration` 读取。初始地点为 `A`、版本为 `1`。工作人员调用 `PUT /api/v1/terminal/configuration`，请求如 `{"site_id":"B"}`，切换到 A、B、C 中一个地点。地点变化产生新版本；历史版本永久保留，不改写已采集事件。终端应在采集时固定地点和版本，离线补传不得替换成最新配置。

## 到访事件

终端调用 `POST /api/v1/visits`，请求示例：

```json
{
  "event_id": "scan-001",
  "session_id": "demo-001",
  "badge_id": "badge-001",
  "terminal_id": "k230-001",
  "site_id": "A",
  "config_version": 1,
  "captured_at": "2026-10-02T14:00:00Z",
  "time_quality": "synced"
}
```

- `event_id` 每次采集唯一，重试必须使用原编号和原内容；重复编号但内容不同返回 409。
- 时间必须带时区。终端已校时用 `synced`；无法校时用 `untrusted`。后者不进入精确分钟统计，去重使用后台接收时间。已校时事件超过后台当前时间 30 秒返回 422。
- 未登记腰牌返回 404；地点与配置版本不符返回 409；未知字段返回 422。
- 同一会话、腰牌、地点、来源的事件在 60 秒内合并。响应 `visit.event_id` 是后台采用的到访编号，可能不是本次发送的编号；后续解锁必须使用响应编号。
- 原事件重试或短时合并返回 `duplicate=true`。终端仍须自行防止二维码持续入镜反复产生事件，并在失败后使用原请求补传。

响应包含 `visit`、`duplicate`、`can_unlock`。`visit` 保留采集时间、接收时间和配置版本。物理扫码来源为 `physical_scan_simulated_site`，表示实物扫码、模拟地点，不表示真实景区人流。工作人员用 `GET /api/v1/visits` 读取记录。

## 解锁请求

工作人员调用 `POST /api/v1/unlock-commands`，提供 `command_id`、响应中的 `event_id`、`badge_id` 和现场读取的 `device_id`。只有匹配登记身份的物理到访才能创建请求；当前只有 A 点的 `qin_formation` 已实现。

请求创建后状态为 `pending`，有效期五分钟。相同到访的重试返回原请求，不创建第二条命令。一个请求编号不得绑定其他到访。工作人员向设备发送后，可调用 `POST /api/v1/unlock-commands/{command_id}/sent`，内容为 `{"device_id":"esp32-test"}`。此接口只记录 `sent`，绝不产生 `confirmed`。设备真实确认接口尚未实现，不能据此展示解锁成功。

工作人员可通过 `POST /api/v1/demo/visits` 生成模拟事件，来源固定为 `generated_simulation`。客户端不能自行指定来源；模拟事件不能控制实物腰牌。

## 已验证与未验证

`uv run pytest -q` 覆盖身份错误、权限隔离、事件重试、短时合并、地点历史、未知字段、模拟来源隔离和后台重启保持，共八项。当前执行环境的沙箱会导致测试客户端线程等待；沙箱外同一测试通过。实物扫码、手机 HTTPS、设备发送及执行确认尚未验收。
