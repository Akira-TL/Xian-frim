# 长安游迹腰牌蓝牙接口

手机主链路采用蓝牙低功耗（Bluetooth Low Energy, BLE），与参考固件共用 NimBLE 协议栈。服务不等待 Wi-Fi。当前v5按用户决定取消出厂地址绑定，以包内001逻辑编号处理演示消息；未配置密钥仍拒绝认证，不提供无回执的解锁命令。

## 当前服务

新增服务使用通用属性配置文件（Generic Attribute Profile, GATT）：

| 对象 | UUID | 能力 |
|---|---|---|
| 活动服务 | `5e994001-64aa-4a10-b1f1-78ce02b3974f` | 主服务 |
| 实物身份 | `5e994002-64aa-4a10-b1f1-78ce02b3974f` | 只读 UTF-8 文本 |
| 本地进度 | `5e994003-64aa-4a10-b1f1-78ce02b3974f` | 只读 JSON |
| 设备随机数 | `5e994004-64aa-4a10-b1f1-78ce02b3974f` | 只读 16 字节，每次读取刷新 |
| 授权／查询请求 | `5e994005-64aa-4a10-b1f1-78ce02b3974f` | 写入并等待响应，137／19 字节 |
| 认证回执 | `5e994006-64aa-4a10-b1f1-78ce02b3974f` | 只读 122 字节 |

标识格式保留 `esp32s3-` 加十二位小写十六进制字符。当前演示值来自包内配置，不再等于每块芯片的出厂地址；同包设备共享逻辑编号，不能据此统计独立游客。网页仍读取并验证协议字段，但演示模式不作出厂身份匹配。旧固件有地址绑定，远端须烧v5，不能只刷新网页。

广播仍保留原名称 `DOIT_TT` 和素材服务 `6e400001-b5a3-f393-e0a9-e50e24dcca9e`。Web Bluetooth 选择设备时按原素材服务过滤，并把新活动服务放入 `optionalServices`。页面使用HTTPS，已有安卓实物连接和认证证据，不承诺任意浏览器都支持。

当前实时进度为 `v=2`，网页兼容旧 `v=1`。示例中的编号只作协议说明：

```json
{"v":2,"device_id":"esp32s3-001122334455","session_id":"demo-001","game_id":"gate_search","unlocked":true,"completed":true,"collected":true,"exhibiting":true,"screen":"playing","placed_mask":7,"mistakes":0,"stage":1,"bonus_collected":0,"exhibit_game":0}
```

进度读取返回同一个本地存储模块的状态，不修改解锁、游戏或收藏。存储未就绪或损坏时读取失败，不能返回伪造的初始状态。后台不得把未签名的工作人员输入当作设备执行证据。

四个布尔字段始终是秦俑进度，不随当前游戏切换含义。`game_id` 为三游戏之一；`screen` 为封面、选择、准备、游玩、结果、收藏、展示、设置对应的 `cover/selection/intro/playing/result/collection/exhibit/settings`。`placed_mask` 为秦俑三片位掩码，`stage` 为当前新增游戏阶段0—3；`bonus_collected` 位0、1分别表示城门、诗句收藏；`exhibit_game` 为0秦俑、1城门、2诗句、3无展示。

新增游戏收藏与展示选择单独持久化，本次游戏阶段在内存中保留，设置返回或换游戏不重置；阶段不宣称断电保存。实时遥测不签名、不写到访或认证统计，断开即清除网页实时状态；秦俑认证仍走原122字节回执。

## 认证操作顺序

消息字节结构以 [腰牌认证消息](腰牌认证消息.md) 为准。读取演示逻辑编号，查询先完成后台挑战和回执认证；解锁再读取设备随机数并提交后台授权。把返回的原始字节写入请求特征，读取回执并原样提交后台；查询写入后台生成的19字节消息。写入成功不表示执行，仍须后台认证回执确认。

随机数使用蓝牙控制器运行时的硬件随机数源，有效三十秒，仅作用于当前连接。成功解锁消费随机数；同一授权在有效期内重试返回原回执，不重复执行。读取新随机数、断开连接或协议栈重置均清除旧授权与缓存。查询不会解锁或改变已有解锁重试缓存。进度未就绪、存储失败、消息长度／认证错误时写入失败，不产生可供后台确认的成功回执。

使用支持长写入的客户端发送完整请求，禁止截断或拆成多次独立特征写入。网页优先使用 `writeValueWithResponse`，再读取回执并核对后台挑战；客户端应串行执行请求和回执读取，防止回执被同连接另一请求替换。

## 验证边界

原生固件、安卓网页连接和认证回读已经有实物证据，见[三游戏与路线核查](../validation/三游戏与动态路线联动核查.md)。自动化不替代真实触摸录像或所有断线组合；历史偶发连接失败仍保留，不宣称长期稳定性通过。

接口设计参考 [Chrome 官方 Web Bluetooth 文档](https://developer.chrome.com/docs/capabilities/bluetooth)，包括 HTTPS、用户主动触发设备选择及 `optionalServices` 的要求。GATT 服务注册采用当前 ESP-IDF 内置 NimBLE 的 `ble_gatts_count_cfg`、`ble_gatts_add_svcs`，以本地 SDK 的头文件和构建结果核验。
