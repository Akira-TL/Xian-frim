# 秦俑图片无损压缩记录

## 范围

用户要求避免在低分辨率屏幕中浪费空间。正式图已经为三片72×46、奖励200×160，高清原图只保留在项目来源目录，不进入固件。此次保持四张 PNG 和所有游戏程序不变，只将 LVGL 转换参数从 `--compress NONE` 改为 `--compress RLE`，同时在默认配置启用 `CONFIG_LV_USE_RLE=y`。保持 ARGB8888，未降低颜色或透明度精度。

当前已有构建缓存同步启用解码器并重新构建；缓存本身不提交。新的构建目录从仓库默认值启用，旧缓存须按素材接入说明核对配置。该变更不添加解锁、收藏或存储重置行为。

## 机械验证

`logs/qin-rle-validation.log`：从实际生成的 C 数组读取压缩数据、压缩头及长度，用仓库原版 `lv_rle_decompress` 解码，逐字节与独立解码 PNG 的 BGRA 像素比较；没有使用转换器自己的压缩结果作为预期值。原生解码器通过宿主编译器构建，使用项目 LVGL 的标准字符串实现，分配函数映射到宿主 `malloc`；不替代设备端分配和显示验证。检查脚本为 `logs/check-qin-rle.py`，仅用于本轮验证。

## 运行边界

RLE 解码需要还原像素缓冲：奖励图128000字节，每片13248字节。设备有 PSRAM，既有图片缓存配置不能作为所有界面均无内存问题的证明。后续需实机启动与实际进入拼图／收藏页观察，不能仅凭完整构建、宿主解码一致就确认实物显示通过。三十分钟、三轮主流程及设置返回实物记录仍未完成。

## 显示反馈与诊断边界

用户实际反馈：“看不见图片，只能看见滑块”。此反馈使实物视觉与设置返回验收不成立；不能因构建、启动或认证成功而忽略。尚不清楚反馈指当前仍在设置页、设置页文字缺失，还是返回游戏后图片缺失，已请求当前屏幕照片，暂不重启或继续叠加显示修改。

诊断技能停在复现阶段：原生图片数据解码检查已经通过，但它不能捕获上述真实显示症状；启动检查也不能判定图片出现。当前还没有已运行且能对该症状判失败的自动检查，未进入根因假设、插桩或修复阶段。没有将“设置页显示滑块”推断为已证明根因，也未声称 RLE 或字体已出错。
