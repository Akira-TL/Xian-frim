# 情景推演接口

`POST /api/v1/simulation`，后台需要工作人员令牌，终端不能调用。推演仅使用请求参数，不读取或写入到访、解锁、设备进度；结果来源固定为 `scenario_simulation`，不属于任何到访来源。

## 参数

`nodes` 必须提供 A、B、C 各一个节点；每个节点包含：

| 字段 | 含义与范围 |
|---|---|
| `site_id` | 节点 A、B 或 C |
| `initial_people` | 假设初始人数，0—10000 |
| `arrivals_per_minute` | 假设每分钟新增到达人数，0—1000 |
| `stay_minutes` | 假设平均停留分钟数，1—240 |

另有不同的 `from_site`、`to_site`，采纳分流比例 `adoption_ratio` 为 0—1，推演分钟数 `duration_minutes` 为 1—120 的整数。人数和速率允许有限小数，它们是估计值，不是对真实人员的计数。参数范围只用于约束演示输入和计算成本，不代表场地容量。

## 固定算法与边界

步长一分钟，上一分钟估计人数为 N、到达率为 λ、停留分钟数为 T，则本分钟离开量为 N/T，下一分钟人数为 `max(0, N + λ - N/T)`。新到达者不在同一步立即离开；算法不模拟个体路径、旅行耗时或真实停留分布。

每分钟分流量为原目标到达率乘以采纳比例。该量从原目标新增到达量扣除，再加入新目标，其他节点不变。只分配新增到达，不把已经在节点的人瞬间迁移。各节点总到达量在分流前后相等；不同停留时间导致离开量不同，因此不保证两种方案总在场估计量始终相等。

响应包含 `generated_at`、一分钟步长、离开量公式、假设标签、完整 `parameters` 和 `series`。每个曲线点含 `minute`、未分流的 `baseline`、采用分流的 `guided`、当分钟的 `diverted_arrivals`。第零分钟是相同初始状态，分流量为零；每组节点按 A、B、C 固定顺序输出。计算不在中间步骤取整，显示时可四舍五入，但不得用显示值重新推进模型。

手算例：A 初始100、到达10/分钟、停留10分钟；B/C 初始和到达均零、停留均10分钟。全部新增到达 A→B，未分流 A 两分钟始终100；分流后第一分钟 A=90、B=10，第二分钟 A=81、B=19。没有将原来的十个到达者同时计在两个节点。

## 显示与验收

两种方案均属于情景推演，曲线必须使用虚线；不将未分流方案称为真实观测，也不宣称“已降低拥堵”。实际扫码若绘制曲线须使用实线并保留腰牌数单位，不能与假设人数混用。

未知字段、重复/缺失节点、自分流、非法数值及超出范围返回 `422`。未授权返回 `401`。网页同源免登录代理已开放这一计算路径，服务端代持内部令牌，用户无需账户。客户端验证请求与响应字段、假设来源、三个节点完整性和分钟步连续性。

`tests/backend/test_simulation.py` 通过公开接口验证独立手算例、参数限制、零分流、零到达、非负约束和事实隔离；网页公开接口测试另验证免登录同源请求、手算输出和不产生到访。
