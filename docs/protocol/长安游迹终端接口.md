# 长安游迹终端到访接口

## 范围与运行

本仓库提供后台接口，不实现或部署 K230 的摄像头、驱动、扫码和屏幕程序。当前会话固定为 `demo-001`，终端固定为 `k230-001`。工作人员免登录网页、实物身份核对、认证解锁及进度同步已接入，当前证据与未通过项见[首版实现状态](../product/首版实现状态.md)。本文件描述终端到访与地图契约，不替代 K230 实物扫码验收。

开发依赖用 `uv sync` 安装。设置不同的 `CHANGAN_OPERATOR_TOKEN` 和 `CHANGAN_TERMINAL_TOKEN` 后，通过 `bash scripts/backend.sh` 前台运行；停止使用终端中断。日志位于 `logs/backend.log`，数据库默认为 `data/changan.sqlite3`。令牌不得提交到 Git。默认仅监听 `127.0.0.1:8000`；手机接入前必须配置 HTTPS，不应将开发服务直接公开。

`/health` 不要求令牌。其他接口要求 `Authorization: Bearer <令牌>`。工作人员令牌不能上报终端事件，终端令牌不能登记设备或解锁。服务启动时拒绝空令牌及相同令牌。开发用交互说明位于 `/docs`，机器可读契约位于 `/openapi.json`。

## 身份与地点

工作人员通过 `POST /api/v1/badges` 登记 `badge_id`、`display_number`、`device_id`。二维码只携带不透明腰牌标识；对接方将识别出的标识放入 `badge_id`，不得从二维码推定实物设备身份或地点。最终二维码文本封装格式待与对接方确定，本接口不依赖特定封装。

工作人员用 `GET /api/v1/badges` 查询登记列表，按 `badge_id` 排序，每项只含上述三个字段，不包含设备密钥。登记后的身份映射不可通过重复登记更换；此列表不能替代现场读取实物设备身份。终端令牌及无令牌访问均返回 401。

地点配置由终端调用 `GET /api/v1/terminal/configuration` 读取。初始地点为 `A`、版本为 `1`。工作人员调用 `PUT /api/v1/terminal/configuration`，请求如 `{"site_id":"B"}`，切换到 A、B、C 中一个地点。地点变化产生新版本；历史版本永久保留，不改写已采集事件。终端应在采集时固定地点和版本，离线补传不得替换成最新配置。

## 到访事件

终端调用 `POST /api/v1/visits`，请求示例：

```json
{
  "event_id": "scan-001",
  "session_id": "demo-001",
  "badge_id": "badge-001",
  "terminal_id": "k230-001",
  "site_id": "A",
  "config_version": 1,
  "captured_at": "2026-10-02T14:00:00Z",
  "time_quality": "synced"
}
```

- `event_id` 每次采集唯一，重试必须使用原编号和原内容；重复编号但内容不同返回 409。
- 时间必须带时区。终端已校时用 `synced`；无法校时用 `untrusted`。后者不进入精确分钟统计，去重使用后台接收时间。已校时事件超过后台当前时间 30 秒返回 422。
- 未登记腰牌返回 404；地点与配置版本不符返回 409；未知字段返回 422。
- 同一会话、腰牌、地点、来源的事件在 60 秒内合并。响应 `visit.event_id` 是后台采用的到访编号，可能不是本次发送的编号；后续解锁必须使用响应编号。
- 原事件重试或短时合并返回 `duplicate=true`。终端仍须自行防止二维码持续入镜反复产生事件，并在失败后使用原请求补传。

响应包含 `visit`、`duplicate`、`can_unlock`。`visit` 保留采集时间、接收时间和配置版本。物理扫码来源为 `physical_scan_simulated_site`，表示实物扫码、模拟地点，不表示真实景区人流。工作人员用 `GET /api/v1/visits` 读取记录。

## 解锁请求

工作人员调用 `POST /api/v1/unlock-commands`，提供 `command_id`、响应中的 `event_id`、`badge_id` 和现场读取的 `device_id`。只有匹配登记身份的物理到访才能创建请求；当前只有 A 点的 `qin_formation` 已实现。

请求创建后状态为 `pending`，有效期五分钟。相同到访的重试返回原请求，不创建第二条命令。一个请求编号不得绑定其他到访。工作人员向设备发送后，可调用 `POST /api/v1/unlock-commands/{command_id}/sent`，内容为 `{"device_id":"esp32-test"}`，其中身份必须替换为实际登记且核对的设备身份。此接口只记录 `sent`，绝不产生 `confirmed`。

工作人员用 `GET /api/v1/unlock-commands` 查询请求列表，按 `created_at` 倒序、`command_id` 排序，返回完整 `UnlockCommand` 字段。读取不改变状态，不自动过期或确认请求；页面必须结合 `expires_at` 判断是否还能发送。终端令牌及无令牌访问均返回 401。

设备确认必须经授权消息写入实物后读取认证回执，再提交 `POST /api/v1/device-reports`。后台验证设备身份、挑战、消息认证和进度约束后，才可能将对应解锁请求更新为 `confirmed`。普通状态查询不会确认解锁请求，手工填写进度布尔值也不被接受；详见[腰牌认证消息](腰牌认证消息.md)。手机网页在明确标注的接口测试到访上已完成真实设备写入与确认，见[手机测试解锁记录](../validation/ADB手机测试解锁与阶段复核.md)；K230 真实扫码链路仍由对接方验收。

工作人员可通过 `POST /api/v1/demo/visits` 生成模拟事件，来源固定为 `generated_simulation`。客户端不能自行指定来源；模拟事件不能控制实物腰牌。

用户授权的演示联调另有 `POST /api/v1/interface-test/visits`，来源为 `interface_test`，由工作人员内部令牌访问；可以沿用实物核对及认证解锁流程，但必须明确标为接口测试，不计真实扫码。该专用入口不是 K230 上报接口，不能把测试记录改为实物扫码来源。

## 已验证与未验证

`uv run pytest -q tests/backend/test_visits.py` 覆盖身份错误、权限隔离、事件重试、短时合并、地点历史、未知字段、模拟来源隔离、后台重启保持、非 ASCII 令牌拒绝，以及工作人员登记/请求只读查询。访问令牌使用 ASCII 字符。既有执行环境曾出现沙箱内测试客户端等待，沙箱外同一测试通过。当前后台全量复查90项通过，不将该数量当作本接口单独用例数；详情与日志见首版实现状态。手机 HTTPS、设备认证解锁及烧录后状态保持已有真实证据，实物扫码及连续三轮／30分钟仍未验收。

## 地图和终端反馈

终端和工作人员均可用各自令牌读取 `GET /api/v1/map`。`source` 查询参数默认为 `physical_scan_simulated_site`，也可选择 `generated_simulation` 或 `interface_test`；三种来源分别查询，绝不合计。响应提供 A、B、C 三个节点、最近一小时五分钟分窗曲线及近十分钟相邻节点转移记录。

- 当前窗口为 `(当前时间−300秒, 当前时间]`，上一窗口为 `(当前时间−600秒, 当前时间−300秒]`。每个节点、每个窗口按不同 `badge_id` 去重，`change` 为两窗口记录数之差。
- `heat` 为 `low`、`medium`、`high` 或 `insufficient`。演示阈值为 0—2、3—5、6 及以上；`demo_thresholds=true`。这些数值不是现场在场人数或安全容量。
- `data_status` 为 `fresh`、`stale`、`missing` 或 `untrusted`。最新已校时扫码或终端反馈超过 90 秒即过期；无反馈为缺失。近十分钟存在未校时事件时，返回不可靠时间标记和排除数量，不计入精确分钟曲线。
- 非新鲜节点必须显示灰色“数据不足”，即使其已记录扫码数为零；不要用零解释为现场空闲。响应数字仅表示已记录、可按时间定位的事件，并不表示采集覆盖完整。
- `updated_at` 是节点最近可靠采集时间，不是页面请求时间。`generated_at` 是本次统计生成时间。迟到上报不能刷新旧数据的采集时间。
- 曲线有 `window_start`、`window_end` 和 `unique_badges`，采用相同去重口径；节点转移按同一腰牌的已校时采集顺序生成，不根据管理员切换配置推定游客移动。

终端用 `POST /api/v1/terminal/heartbeat` 提交 `terminal_id`、`site_id`、`config_version`、带时区的 `captured_at`。建议每 15 秒反馈一次，必须已校时；后台校验地点历史配置、拒绝未来超过 30 秒的时间。反馈只说明终端最近采集状态，不能增加到访或解锁。工作人员令牌不能调用此接口。模拟来源不借用物理终端反馈作为数据新鲜性的证据。

地图接口测试覆盖手算去重腰牌数、精确窗口边界、过期及未校时数据、反馈迟到、来源隔离、节点转移和读取权限。早期阶段累计26项不是当前全量测试数量，最新记录以首版实现状态为准；测试数量本身不证明真实终端部署。
