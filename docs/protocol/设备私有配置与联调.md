# 设备私有配置与联调

以下操作仅针对 ESP32-S3 腰牌，不操作 K230。用户已确认原固件曾备份，项目脚本不重复备份，也不执行整片擦除。

## 配置顺序

1. 在能访问设备的 WSL 环境运行 `bash scripts/device.sh inspect /dev/ttyACM0`，从 `logs/device-inspect.log` 确认芯片、实际闪存容量及出厂 MAC。检查可能重启设备，但不写入固件。
2. 将 MAC 去除冒号并转为小写，加前缀 `esp32s3-`；运行 `bash scripts/provision-device.sh <设备身份>`。不能使用文档示例身份配置实物。
3. 私有密钥保存在 `data/device-keys.json`，生成头文件在 `data/generated/changan_device_key.h`，文件权限均为 `0600`，均被 Git 忽略。重复运行复用原密钥，不轮换；现有配置身份不匹配或权限过宽时拒绝覆盖。脚本不输出密钥，不烧录。
4. 后台设置 `CHANGAN_DEVICE_KEYS_PATH` 指向该私有 JSON 文件。固件必须重新配置和构建，使 CMake 加载私有头文件：先加载 `/home/Akira/github/esp-idf/export.sh`，执行 `idf.py -B build reconfigure`，再执行 `bash tools/build.sh`。
5. 核对实际闪存与分区大小后，运行 `bash scripts/device.sh flash /dev/ttyACM0`；监视入口为 `bash scripts/device.sh monitor /dev/ttyACM0`。日志位于 `logs/`，不要将密钥或私有配置复制进去。

缺少头文件的固件可以构建，但拒绝访问认证特征。配置设备 MAC 与实物不符也拒绝访问。游戏保存与蓝牙配对数据仍按原项目分区管理，不应为了联调清空 NVS。

## 安全与验证边界

本地配置没有替代安全启动或闪存加密；具有固件读取能力的人仍可能取得密钥，因此本方案定位为受控演示系统，而非生产设备防克隆方案。固件二进制同样包含密钥，不得公开上传或当作普通演示附件分发。

配置工具测试使用临时目录与独立身份，验证设备绑定、密钥复用、文件权限和符号链接拒绝。此测试不证明真实设备已烧录、接受授权或完成触摸游戏；这些必须由实机记录证明。
