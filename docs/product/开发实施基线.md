# 《长安游迹 · AI寻迹吧唧》开发实施基线

本文档将[产品需求文档 2.0](长安游迹_AI寻迹吧唧_PRD_2.0.md)收敛为当前可执行的开发目标。产品需求文档 2.0 是现行产品目标来源；[产品需求文档 1.0](长安游迹_AI寻迹吧唧_PRD.md)仅用于历史追溯，其中 NFC 打卡、修改 ESP32 固件和 48 小时开发计划均不再适用。

## 1. 当前开发目标

在 24 小时内完成一条真实、可验收的硬件闭环：

1. K230 摄像头读取腰牌背面的唯一二维码；
2. 后台保存带会话、地点、腰牌和时间的到访事件；
3. 工作人员在安卓手机网页核对到访事件与实物腰牌；
4. 手机通过现有设备接口为正确腰牌解锁预置的《秦俑归阵》；
5. 儿童在腰牌触摸屏上完成游戏，获得并展示收藏图；
6. 七英寸终端展示三节点示意地图与打卡热度；
7. 后台生成有数据依据的下一站建议，电脑看板展示趋势与明确标注的情景推演。

首版只保证一枚腰牌、一个活动会话、一套 K230、一台安卓手机和一个完整小游戏。第二、第三个游戏属于增强项，不得挤占主链路修复时间。

## 2. 已确认边界

| 项目 | 当前决定 | 工程影响 |
|---|---|---|
| 腰牌固件 | 不修改、不刷写 | 不在 `main/` 和 ESP-IDF 组件中实现本次产品功能 |
| 腰牌扩展方式 | 使用现有工具上传游戏、脚本、图片和视频 | 首轮先验证真实上传格式、运行入口和状态能力 |
| 到访识别 | K230 摄像头识别腰牌二维码 | 删除 NFC 相关设计与开发依赖 |
| 地点身份 | 来自 K230 当前配置 | 二维码只保存腰牌身份，不写死地点 |
| 解锁操作 | 工作人员在安卓手机网页执行 | 未匹配设备身份或没有真实到访事件时禁止解锁 |
| 游戏运行位置 | 腰牌本地触摸屏 | 手机和后台不能代替腰牌完成游戏或伪造通关 |
| 演示节点 | 一套 K230 切换 A、B、C 三个模拟地点 | 历史事件必须保存扫码时的地点与配置版本 |
| 后台与 AI | 可使用电脑、互联网和大模型接口 | 密钥只在服务端；统计由确定性逻辑计算 |
| 数据口径 | 参与腰牌的近期去重打卡与节点转移 | 不宣称实时在场人数、拥堵概率或真实儿童总数 |

## 3. 当前事实与证据限制

### 3.1 已确认

- 当前工作区包含一套 ESP32-S3 圆形屏吧唧参考源码和原始压缩包；
- 参考源码包含圆屏、触控、音频、素材传输、Wi-Fi、蓝牙配置和本地存储相关实现；
- 参考源码已在 ESP-IDF 5.4.1 下完整构建通过；
- WSL 中的 `/dev/ttyACM0` 已只读识别为 ESP32-S3 rev 0.2、8 MiB PSRAM、USB Serial/JTAG；
- 本轮未向设备烧录固件，也未擦除设备数据。

### 3.2 不能据此推定

参考源码能够构建，不等于实物正在运行同一版本。未经过实机操作前，不得据此写死以下内容：

- 游戏或脚本语言、包格式和启动入口；
- 蓝牙低功耗（Bluetooth Low Energy, BLE）服务 UUID、命令编码或授权方式；
- Web Bluetooth、Wi-Fi 或其他控制链路中哪一种已经可用；
- 脚本能否保存解锁、通关和收藏状态；
- 外部是否能读取设备身份、启动游戏、传递参数或回读结果；
- 视频、动画、图片和音频的实际编码、尺寸、帧率与容量限制；
- 当前实物固件与参考仓库之间的版本关系。

参考源码在本项目中只作为接口调查和行为比对资料。PRD 2.0 未明确允许前，不把对参考固件的修改作为交付路径。

## 4. 目标系统职责

### 4.1 腰牌内容包

- 开场内容、初始收藏与锁定状态；
- 《秦俑归阵》触摸游戏；
- 本地胜利判定、一次性奖励与复玩；
- 在现有运行环境允许的范围内保存解锁、通关、收藏和当前展示状态；
- 提供真实可用的外部解锁入口和结果读取方式；若环境不支持，明确记录阻塞或降级范围。

### 4.2 K230 终端

- 摄像头读取并校验二维码；
- 为扫码事件附加 `terminal_id`、当前 `site_id`、配置版本和时间信息；
- 同一二维码持续入镜时只产生一次事件；
- 后台不可达时显示“待同步”，有本地队列时使用原事件编号补传；
- 七英寸屏展示三节点地图、当前扫码反馈、近期热度和建议；
- 支持管理员切换模拟地点，但不得改写旧事件。

### 4.3 后台服务

- 管理活动会话、腰牌、设备、地点和终端配置；
- 保存到访事件，并合并同一会话、腰牌和地点 60 秒内的重复扫码；
- 创建与真实到访事件绑定的解锁请求；
- 区分指令已发送、设备已确认、失败、未知和人工核验；
- 合并不回退的游戏与收藏状态；
- 计算近期去重打卡数、趋势和节点转移；
- 保存 AI 推荐的输入快照、输出、校验结果和来源；
- 将模拟数据与真实扫码数据隔离，禁止模拟事件向实物腰牌下发解锁。

### 4.4 手机与电脑页面

- 手机页面负责待处理到访、设备核对、连接、解锁、回读、重试和状态说明；
- 电脑页面负责全景地图、趋势、活动进度、AI 建议、操作记录和情景推演；
- 页面至少区分后台在线、手机已连接设备、设备已执行三种状态；
- 手机与电脑读取同一后台数据，不维护两套手工数字。

## 5. 核心状态与不变量

状态顺序为：

`到访已记录 → 解锁待发送 → 解锁已发送 → 游戏已解锁 → 游戏已完成 → 奖励已收藏 → 后台已同步`

必须保持以下不变量：

1. “解锁已发送”不等于“游戏已解锁”；
2. 到访、通关、奖励和同步状态互不替代；
3. 同一请求重试不新增到访、不清空进度、不重复发奖；
4. 已完成状态不得被较旧的后台状态回退；
5. 没有可靠回读时显示“待核实”，不能显示自动执行成功；
6. 下一站建议不自动解锁，被推荐地点仍需真实扫码；
7. 后台生成的模拟数据不得改变实物腰牌状态。

核心记录至少使用以下标识：

- `session_id`：活动会话；
- `badge_id`：二维码中的不透明腰牌身份；
- `device_id`：实物设备的稳定身份；
- `terminal_id`：K230 终端；
- `site_id`：扫码时的地点；
- `event_id`：一次到访事件；
- `command_id`：一次可重试的解锁请求；
- `game_id` 与 `reward_id`：游戏和收藏奖励。

## 6. 24 小时实施阶段

### 阶段 0：实机适配门禁（0—2 小时）

- 使用现有工具运行一个最小触摸页面；
- 验证外部启动或更新测试内容；
- 读取断连后仍稳定的设备身份；
- 验证状态保存、结果回读或明确人工核验边界；
- 验证至少一种图片和视频格式；
- 验证 K230 摄像头可读取一个测试二维码；
- 选定且只选定一种腰牌控制主链路。

通过门槛：手机能够使正确实物腰牌发生可重复、可解释的页面变化，K230 能够稳定读码。若任一关键接口不存在，立即记录阻塞并调整演示范围，不继续假设接口可用。

### 阶段 1：最短跨端链路（2—5 小时）

- 建立二维码、`badge_id` 与实际 `device_id` 的人工核对登记；
- K230 提交真实到访，手机看到同一条待处理记录；
- 手机拒绝身份不匹配的设备；
- 对正确设备发出测试解锁并区分发送与执行结果。

通过门槛：一次真实扫码和一次工作人员操作能使正确腰牌显示对应测试页。

### 阶段 2：游戏与收藏闭环（5—9 小时）

- 完成《秦俑归阵》的三片点击选择玩法；
- 正确、错误、提示、退出和复玩路径均可操作；
- 游戏本地判断成功，奖励进入收藏并可设为展示；
- 重复通关不重复计数和发奖；
- 离开手机通信范围后，已解锁游戏仍可本地完成。

通过门槛：实物腰牌可从锁定状态经真实解锁完成游戏、收藏和展示。

### 阶段 3：可靠性与七英寸地图（9—13 小时）

- 实现扫码合并、事件和命令去重、超时与断线重试；
- 手机展示真实连接与执行状态；
- 七英寸屏展示三节点地图、近期去重打卡数、变化和更新时间；
- 数据过期显示“数据不足”，不显示“空闲”。

### 阶段 4：AI 推荐与看板（13—17 小时）

- 后台确定性计算趋势和合格候选节点；
- 大模型只在候选中提出建议并生成简短说明；
- 后台校验地点、字段、时效和约束；
- 超时使用有来源标记的规则建议或显示不可用；
- 电脑端以实线展示观测数据，以虚线展示标注参数的情景推演。

### 阶段 5：验收与演示（17—24 小时）

- 修复主链路阻断问题，未完成的增强项从演示路径移除；
- 执行 PRD 2.0 的 A01—A16 验收并保存证据；
- 连续运行 30 分钟并完成三轮主流程；
- 演练三分钟展示，录制真实备用操作视频；
- 整理限制、数据来源、外壳文件和提交材料。

## 7. 推荐工程边界

在实机适配门禁通过后，如继续使用单体仓库，建议按交付物建立以下顶层模块：

```text
badge-content/          # 腰牌脚本、游戏与媒体资源
apps/k230-terminal/     # K230 扫码与七英寸界面
apps/operator-web/      # 安卓工作人员页面
apps/dashboard-web/     # 电脑管理看板
services/backend/       # 到访、解锁、状态、统计与 AI 推荐
docs/                   # 需求、接口、验收与演示资料
```

实际脚本语言、K230 运行时和网页技术栈必须在阶段 0 根据设备与现有工具确定。在此之前不创建假接口、不搭建无法连接实物的空壳业务系统。

## 8. 当前下一步

开发下一步不是继续修改 ESP32 固件，而是完成阶段 0 的实机适配门禁：找到并运行现有内容上传与控制工具，确认游戏脚本格式、稳定设备身份、外部解锁入口、状态持久化、结果回读和媒体限制；同时确认 CanMV-K230-LP4 V3.0 的 SDK、摄像头、七英寸屏和网络能力。

阶段 0 的结果将决定腰牌适配器和 K230 程序的真实接口。在门禁通过前，后台、手机页和游戏只能设计契约，不应宣称已经具备端到端实现条件。
