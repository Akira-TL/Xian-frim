# 腰牌二维码资源

001号正式登记身份为 `badge-001`，不是显示编号 `001`、网址或蓝牙名称。二维码只编码这九个ASCII字符，无前后空白、换行、地点、个人信息或密钥。

## 可直接使用

- `assets/qr/badge-001.svg`：白底黑码矢量图片，用于交给打印或装配负责方；不要裁掉白边。
- `assets/qr/badge-001.png`：同内容点阵图片，便于屏幕查看和纸样测试。

外壳建模与贴装由用户或其负责方处理，本项目不指定未经测量的毫米尺寸、不宣称实物已贴装。优先使用原比例矢量文件，二维码区域不要覆盖纹样、标志或反光膜；打印后的识别距离和角度由负责方实测。

## 生成与核查

```bash
UV_CACHE_DIR=/tmp/xian-frim-uv-cache uv run scripts/assets/prepare-badge-qr.py
```

脚本通过 [Segno 官方实现](https://pypi.org/project/segno/1.6.6/) 生成标准二维码，禁用微型二维码，保留四模块白边、H级纠错；再通过不同实现 [ZXing-C++](https://github.com/zxing-cpp/zxing-cpp/blob/master/wrappers/python/README.md) 读取PNG，必须精确等于 `badge-001` 才输出。依赖由脚本锁定，不加入后台或固件运行依赖。已有同内容资源允许重复检查，不覆盖不同内容的文件。

可用 `--badge-id` 生成另一个符合标识格式的码，但须先单独登记；生成文件本身不登记腰牌、不创建到访、不解锁设备。新文件独立解码不等于K230摄像头、贴纸或全部光照条件已通过。现有实物背面旧码是否相同仍须实际读取，不擅自宣称兼容。

本次PNG为330×330像素。生成、独立解码、重复一致和非法路径型标识拒绝日志位于 `logs/badge-qr-generation.log`、`logs/badge-qr-repeat.log`、`logs/badge-qr-invalid.log`。
