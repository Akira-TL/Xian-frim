# 下一窗口趋势估计接入记录

2026年10月3日，补齐 PRD 2.0 第14.2节所述简单平滑估计。最近一小时观测实线图已存在，但不等于下一窗口估计；本次单独展示，并保持单位、来源及假设明确。

## 口径与限制

后台以当前五分钟有效到访次数的0.7权重与前五分钟的0.3权重计算下一五分钟估计。两窗等长，故到访率加权后乘五分钟等价于次数加权。此处是有效到访次数，不是地图的去重腰牌数，也不是在场人数。

两个窗口各至少一条可靠记录且节点数据新鲜才估计。缺失、过期、时间不可靠或样本不足返回空值并说明状态。网页后台断线时不显示旧数值估计。来源、会话、窗口边界与现有观测保持一致；计算不改变推荐、解锁、进度、热度或K230地图接口。

## 证据

- `tests/backend/test_statistics.py` 新增两项测试：公开活动接口确认当前2次／前窗3次得2.3次，同一腰牌只计1枚但计多次有效到访；拒绝缺失、过期、不可靠、单窗样本不足，排除未来、其他来源、其他会话及左边界之外事件。
- 活动与统计针对性检查17项通过；现有框架弃用警告保留，不为比赛迁移测试框架。
- 网页类型检查、生产构建通过；日志 `logs/trend-estimate-web-build.log`。服务已重新启动并集成至正式域名。启动初期一次查询返回502，启动完成后重新查询成功，不把初期失败掩盖为全程在线。
- 隔离网页代理和认证控制各8项通过；日志 `logs/web-gateway-test.log`、`logs/web-control-test.log`。隔离数据库不修改真实腰牌进度。
- 正式项目浏览器实际点击“生成演示数据”，再通过已开放模拟到访接口补一条前窗生成记录；该记录返回 `generated_simulation`、`can_unlock=false`，不算实物扫码、不触发模型、不改终端地点配置。
- 浏览器响应与实际渲染逐节点比对：A当前6次／前窗1次，估计4.5次；B当前3次／前窗0次、C当前1次／前窗0次均显示“两窗样本不足”。页面无横向溢出。结果 `logs/trend-estimate-browser-generated.json`。
- 默认实物来源无数据时，三节点实际显示“暂不估计（尚无数据）”，不是零人或空闲。

该证据证明实现与公式、拒绝条件及正式页面一致，不证明预测准确率或分流有效性。未进行儿童时长实验、真实客流校准或用户已取消的长时间稳定性测试。
