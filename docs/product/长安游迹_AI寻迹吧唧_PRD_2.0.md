## 2. 产品定位与价值假设

### 2.1 产品定位

长安游迹是一枚随游览逐步解锁内容的文化腰牌。孩子通过到点打卡、触摸小游戏和徽章收藏探索文化内容；景区获得参与腰牌的到访记录，并据此提供更合适的下一站建议。

### 2.2 面向的具体问题

| 使用者 | 需要改善的体验 | 产品回应 |
| --- | --- | --- |
| 儿童 | 单向听讲缺少可操作目标和即时反馈 | 每个节点提供短任务，完成后得到可佩戴展示的收藏图 |
| 家长或研学带队人 | 孩子不清楚下一站做什么，游览参与感难以持续 | 腰牌显示已完成内容、待探索地点和下一站提示 |
| 景区工作人员 | 缺少参与游客在节点间移动的可用记录 | 二维码产生带时间、地点和腰牌编号的到访事件 |
| 景区运营人员 | 热门节点集中、冷门内容不易被注意 | 结合打卡热度和文化任务，提供分流建议及展示理由 |

上述问题和改善效果是产品假设。比赛原型验证可用性、操作链路和数据计算，不把尚未开展的用户访谈、付费意愿或分流效果写成已有成果。

### 2.3 核心产品动作

孩子到达一个文化节点后，腰牌获得该节点的互动任务；通关获得收藏奖励，再收到适合继续探索的地点建议。景区能够看到这次到访如何影响节点热度，工作人员能够决定是否采纳推荐。

## 3. 角色与使用边界

| 角色 | 可执行操作 |
| --- | --- |
| 儿童游客 | 观看开场、展示二维码、在腰牌玩游戏、查看收藏、设置展示图 |
| 家长或带队人 | 协助扫码与佩戴，查看游玩进度和建议 |
| 工作人员 | 在手机选择扫码事件、连接对应腰牌、发送解锁指令、处理失败 |
| 景区管理人员 | 查看全局热度、趋势和建议，运行明确标注的情景推演 |
| 演示管理员 | 切换模拟节点、加载演示数据、重置测试会话 |

设计年龄暂按6—12岁作为交互假设，不采集真实年龄。儿童界面优先图形、大触控区和短句，避免长段说明、强制限时及惩罚性反馈。

首版由工作人员持有一台安卓手机，一次操作一枚腰牌。游客不需要各自安装应用或保持自己的手机连接。正式规模化部署的自动派发、多设备并发及运营权限细分属于后续版本。

手机端仅交付网页，工作人员同样无需安装应用；不开发 Android 原生应用，也不以安装应用作为演示条件。演示网页默认免登录，所有人均可使用；服务端内部凭据及腰牌身份、签名回执校验仍保留。USB 调试若用于本机网页联调，只是调试通道，不改变网页交付形式。

用户指定网页地址为 `https://babelbeast.com/xks`，电脑看板为 `https://babelbeast.com/xks/dashboard`。手机可先选择已登记腰牌、核对实物身份并读取认证进度，不要求先到访；此查询不产生到访、解锁或奖励。解锁仍须对应的合格到访与设备认证回执。

## 4. 硬件与软件职责

| 组成 | 负责 | 开发边界 |
| --- | --- | --- |
| ESP32腰牌 | 播放内容、触摸游戏、保存解锁与通关状态、展示收藏图 | 使用现有运行环境，不修改固件；脚本可调用的接口以实测为准 |
| 背面二维码 | 唯一腰牌身份 | 不包含儿童姓名、联系方式、无线密码或控制凭证 |
| K230与摄像头 | 识别二维码、产生到访事件、显示扫码反馈 | 不承担所有业务后台，不把二维码识别单独包装成AI模型 |
| 7英寸屏 | 景区节点地图、打卡热度、当前扫码状态、下一站建议 | 暂不假定该屏支持触摸，必要操作在手机完成 |
| 安卓手机网页 | 工作人员操作、设备连接、指令发送和结果确认 | 优先复用现有设备接口，保持页面前台可见 |
| 后台服务 | 身份对应、到访去重、指令记录、统计、AI推荐 | 大模型密钥只放服务端，业务计算与模型输出分开 |
| 电脑网页 | 全景地图、趋势曲线、操作记录、情景推演 | 读取与手机相同的后台数据，不另维护一套手工数字 |

后台可以部署在可通过HTTPS访问的服务器，手机与电脑打开同一系统的不同页面。若采用现场电脑部署，需提前解决手机访问、证书和网络连通问题，不能默认手机网页能访问电脑的`localhost`。

| 节点 | 内容 | 首版范围 |
| --- | --- | --- |

## 6. 完整使用流程

### 6.1 活动前准备

1. 通过设备现有工具上传开场视频、初始图片、游戏资源和奖励图片。
2. 建立腰牌编号、背面二维码与实际设备身份的对应关系。
3. 加载新的测试会话，确保景点游戏与奖励均未解锁。
4. 连接安卓手机，读取设备身份并核对屏幕提示。
5. 配置K230所代表的地点、地图与后台连接。
6. 演示人员确认真实记录与模拟背景数据的显示模式。

### 6.2 领取与开机

开场视频短暂播放，可跳过；播放结束进入欢迎页。初始收藏册只显示通用徽章，景点游戏入口暂不显示或显示无法进入的锁定卡片，不能提前游玩。

欢迎页建议文案：“带我去探索长安。到景点后，把背面的二维码给终端看一看。”首次接触扫码流程时，工作人员示范如何翻转腰牌。

### 6.3 到达与扫码

儿童将背面二维码对准K230摄像头。终端识别身份，在后台保存到访后显示：“001号腰牌，秦俑工坊打卡成功。”手机出现对应的待处理记录。

二维码识别成功与后台记录成功是两个状态。后台暂不可达时，终端显示“已识别，记录待同步”，不能同时宣称已经完成在线解锁。若终端有可用本地队列，恢复网络后以原事件编号补传。

### 6.4 工作人员解锁

工作人员在手机打开该到访事件，页面显示腰牌编号、地点、到达时间、连接状态及即将解锁的游戏。连接到的设备身份匹配后，“解锁本点游戏”按钮才可用。

点击后，后台产生一次解锁请求，手机通过现有设备接口发送。收到设备确认并核实对应状态后，手机显示“已解锁”，腰牌出现《秦俑归阵》入口。推荐默认停留在解锁成功页，由孩子点击“开始”，避免突然中断正在查看的内容。

### 6.5 游戏、通关与收藏

孩子在腰牌上完成拼接。游戏脚本在本地判断成功，保存本次完成状态，解锁预置奖励图，并进入庆祝画面。孩子可选择“设为展示”或“放入收藏”。再次进入该游戏可以重玩，但不重复发放奖励。

通关与奖励展示不得依赖孩子一直停留在工作人员手机的蓝牙范围内。状态先在腰牌保存；已有回传接口时立即同步，否则下次连接再补同步。若现有脚本环境不支持持久化或回传，需要在首轮适配验收中明确，不能以手机按钮代替设备实际通关。

### 6.6 推荐下一站

后台读取已完成节点、近期打卡热度、可达节点和内容配置，大模型从合格节点中提出下一站建议。规则校验通过后，终端和手机展示建议；腰牌若已有文本或配置更新接口，可同步显示简短提示。

推荐不代替到访。即使推荐B点，也只有在B点实际扫码后才能解锁B点游戏。工作人员可保留原路线或选择其他可达节点。

## 7. 腰牌外壳与交互设计

### 7.1 腰牌结构

外壳采用长安腰牌的视觉语言：上部挂绳孔、中央圆形屏、下部简洁文字或纹样。采用圆角与平滑边缘，避免把挂绳受力直接传到屏幕或电路板。

尺寸必须依据现有吧唧测量确定，不沿用上一版未经验证的80毫米尺寸。建模前记录本体最大外径、厚度、屏幕可视范围、充电口、扬声器孔、按键、螺丝和散热空间。

背面二维码应位于平面，保留完整空白边缘，避免深色纹样、金属反光膜或弧面覆盖；先用普通纸样验证扫码距离和角度，再固定打印尺寸。外壳保留原充电与操作入口。

### 7.2 页面与状态

| 页面 | 内容与操作 | 进入条件 |
| --- | --- | --- |
| 开场页 | 短视频、跳过入口 | 开机或演示重置 |
| 初始首页 | 通用徽章、到点提示、收藏入口 | 未解锁任何景点 |
| 解锁成功页 | 景点名、游戏名、开始按钮 | 设备已实际接收解锁 |
| 游戏页 | 触摸任务、提示、退出 | 对应关卡已解锁 |
| 通关页 | 完成反馈、奖励图、设为展示 | 本地通关判定成功 |
| 收藏册 | 已获得图片、当前展示标识 | 初始或通关后 |
| 日常展示页 | 选定徽章图，可选少量状态文字 | 用户主动选择 |
| 游戏设置页 | 亮度、音量、返回进入前的游戏视图 | 首页或游戏中主动进入 |

2026年10月3日用户反馈要求：设置必须在游戏内部完成，不再跳入旧固件应用列表；返回恢复进入前的视图与已放置碎片，不重新开始游戏，也不清除解锁、通关、收藏或展示记录。亮度和音量沿用设备已有存储接口，亮度最低保留10%，避免误调至黑屏。

圆形屏幕的主要文字、拼接槽和触控按钮放在中央安全区域，避免将“退出”“确认”等按钮放到裁切边缘。触控目标暂以不小于屏幕直径约15%作为设计起点，再用实机手指操作调整。

开场视频和奖励动画按现有固件实际支持的编码、尺寸和帧率准备，不能默认支持任意MP4或高帧率动画。音效可关闭，不阻断游戏逻辑。

## 8. 游戏内容规格

### 8.1 必做游戏 秦俑归阵

目标体验：孩子完成一个约30—60秒的简单拼接任务，得到“秦俑守护”收藏图。时长为设计目标，尚未经过儿童测试。

| 要素 | 规格 |

通关后可显示一句经过核对的文化说明。画面属于文化启发的游戏示意，不标注为真实文物修复过程或考古复原结论。文化文字与图片出处在素材清单记录。

### 8.3 增强游戏 诗句补全

每题提供两个选项，共两题，不输入文字。诗句、作者、出处由人工核对。选错可重试，通关解锁“诗意长安”图。未实装的游戏在演示界面标注为预览，不使用可点击的假入口。

## 9. 游戏与奖励状态

### 9.1 独立保存的状态

| 状态 | 含义 |
| --- | --- |
| 到访已记录 | 后台已保存对应节点的扫码事件 |
| 解锁待发送 | 工作人员尚未发送，或设备离线 |
| 解锁已发送 | 通信层已发出请求，尚无可靠执行确认 |
| 游戏已解锁 | 设备确认本地游戏可进入 |
| 游戏已完成 | 腰牌本地游戏逻辑判定通关 |
| 奖励已收藏 | 对应奖励已进入本地收藏列表 |
| 后台已同步 | 后台收到与本次设备状态相符的结果 |

“已发送”不能直接改成“游戏已解锁”。游戏通关、奖励收藏与到访统计也不能互相代替。

### 9.2 持久化与重复操作

以`session_id + badge_id + game_id`标识一次活动中的游戏进度，以`session_id + badge_id + reward_id`限制重复奖励。断线重发使用同一个请求编号，设备重复接收时返回当前状态，不重复清空进度或发放奖励。

已通关后的解锁请求只能返回“已完成，可重玩”。网络恢复同步不得把已完成状态回退为未解锁。设备与后台状态冲突时保留双方记录，优先核实设备实际状态；没有回读能力时显示“待核实”。

“重置演示”是管理员单独操作，只影响指定测试会话和测试腰牌。清理后台记录与清理设备脚本状态需要分别确认结果，不能通过后台清空假装设备已复位。

## 10. 二维码与设备身份

背面二维码使用固定、不透明的腰牌标识。界面可显示易读编号“001”，后台使用唯一`badge_id`。终端解析二维码时检查格式和已登记状态，未知编号提示“请工作人员登记”，不执行自动控制。

地点标识来自终端配置，不存入固定腰牌二维码。时间由已校时终端产生并记录后台接收时间；无法校时的离线事件标记时间质量，不能直接用于精确分钟趋势。

登记流程为：读取二维码 → 连接实物设备 → 读取设备稳定身份 → 工作人员核对 → 保存对应关系。二维码内容、蓝牙广播名称和底层无线地址都不能单独充当控制授权。若现有固件要求设备票据或原控制平台授权，适配必须沿用该要求。

连续识别同一二维码时，终端在目标移出画面前只产生一次事件；后台使用事件编号做幂等处理，并对同一会话、腰牌和地点60秒内的重复扫码合并为一次到访。重试解锁不会新增到访。

## 11. 通信实现与设备适配

### 11.1 24小时推荐路径

| 链路 | 推荐方式 | 前置条件 |
| --- | --- | --- |
| K230到后台 | 使用已跑通的有线或无线网络发送到访事件、获取地图状态 | 验证板型、网络驱动、证书与连接可用 |
| 安卓手机到后台 | HTTPS网页查询事件、提交工作人员操作、显示结果 | 同源服务或正确配置跨域访问 |
| 安卓手机到腰牌 | 优先复用已存在的蓝牙低功耗控制接口；若现有工具走Wi-Fi，则沿用该路径 | 确认脚本启动、状态设置及回读能力 |
| 腰牌内游戏与收藏 | 由预置脚本本地执行 | 现有脚本环境提供触摸、媒体、状态保存等必要能力 |
| 电脑到后台 | 与手机共用接口的管理页面 | 不要求电脑直连腰牌 |

蓝牙与Wi-Fi不要求同时启用。选择已跑通的一种作为腰牌控制主路，避免在24小时内同时开发两套适配。K230无需承担手机到腰牌的无线控制。

采用Web Bluetooth时，安卓浏览器需支持该接口，网页处于安全上下文，并由用户点击选择设备。不能将微信内置浏览器或任意安卓浏览器都视为兼容。手机页面保持前台，断线后显示重连入口。

### 11.2 首轮必须检查的现有能力

| 能力 | 验证方式 | 通过条件 |
| --- | --- | --- |
| 脚本上传和运行 | 使用现有工具运行一个简单触摸页面 | 腰牌可显示并响应触摸 |
| 外部启动或参数更新 | 通过原接口选择测试脚本，或更新脚本读取的状态 | 实物页面发生可重复、可解释的变化 |
| 稳定设备身份 | 读取设备身份，与二维码登记对应 | 断连重连后仍能匹配同一腰牌 |
| 状态保存 | 保存解锁与收藏状态，重新打开脚本并按允许方式重启验证 | 状态未丢失 |
| 结果回读或回传 | 查询脚本状态、读取完成事件或使用现有结果接口 | 能分辨发送成功与执行成功 |
| 媒体加载 | 播放现有格式视频、切换预置图片 | 能稳定展示且不会破坏游戏状态 |

具体脚本语言、文件格式、蓝牙通用属性配置文件（Generic Attribute Profile，GATT）服务UUID、命令编码和回调格式，不在没有实测前指定。

### 11.3 适配原则

新增业务代码对上提供“识别设备、读取状态、解锁关卡、读取完成结果”等逻辑操作，对下映射为原有真实接口。文档中的操作名称是待实现的软件契约，不代表设备已经提供同名命令。

如果当前固件只支持外部选择脚本，而不支持向脚本传参，可以考虑以一个活动入口脚本维护进度，并由已有资源选择机制切换内容；具体是否成立仍要以脚本可用接口验证。不能假定任意脚本都能访问蓝牙、网络或整个文件系统。

若设备完全没有可用外部启动或状态控制能力，手机解锁的关键路径尚未成立：应报告适配阻塞，不偷偷改成手机播放游戏或仅在后台点亮成功。若只有结果回传缺失，可将现场观察标记为“人工核验”，与“设备自动确认”分别记录；此时属于降级演示，不能宣称完成全自动双向同步。

## 14. 数据指标与人流估计口径

### 14.1 可以直接统计的指标

| 指标 | 定义 | 不应解释为 |
| --- | --- | --- |
| 节点5分钟去重打卡数 | 在该地点最近5分钟产生有效到访的不同活动腰牌数 | 当前区域实际在场人数 |
| 节点累计到访人次 | 合并短时重复扫码后的有效到访次数 | 全景区门票入场人数 |
| 活动参与腰牌数 | 当前活动至少出现一次有效到访的不同腰牌数 | 所有游客总数或真实儿童人数 |
| 到访变化量 | 当前5分钟窗口去重数减去前一个不重叠5分钟窗口的去重数 | 拥堵概率 |
| 节点转移 | 同一活动腰牌相邻有效扫码地点的有向关系 | 两点之间的精确移动轨迹 |
| 扫码间隔 | 相邻扫码时间差 | 前一个景点的真实停留时长 |
| 游戏完成率 | 设备确认完成数除以设备确认解锁数 | 儿童真实兴趣类型或学习效果 |

真实儿童与腰牌可能不是一一对应，原型不使用人脸识别、手机号或身份信息来强行建立对应。

热度阈值由活动管理员配置。演示时可使用低0—2、中3—5、高6及以上的5分钟去重打卡数作为示例阈值，界面明确“演示阈值”。它们不代表任何真实场地的安全容量。

### 14.2 趋势估计

首版可以用最近两个5分钟窗口的到访率计算简单平滑估计，例如取当前窗口权重0.7、上一窗口权重0.3。下一窗口估计到访量为平滑到访率乘以5分钟，并限制结果不小于0。

这是一项明示假设的统计估计，不是已训练的人流预测模型，也不生成未经校准的拥堵概率。数据量不足、设备离线或时间质量不可靠时显示“暂不估计”。没有真实验证数据时，不展示预测准确率。

### 14.3 人流变化情景推演

电脑端可显示“如果引导部分参与者前往其他节点，曲线可能如何变化”。输入包括假设初始人数、到达率、停留时间和采纳推荐的比例。

每一步估计人数按“上一步估计人数＋估计到达人数－估计离开人数”更新，下限为0。被引导的人从原目标到达量中扣除后，再计入新目标，避免同一人同时出现在两个分支。界面展示默认参数并允许工作人员调整。

预测曲线使用虚线并标注“情景推演”。实际扫码观测使用实线。推演不参与真实解锁、真实完成率或现场安全决策。没有实际干预试验时，不把两条模拟曲线的差距称为“已降低拥堵”。

## 15. AI推荐设计

### 15.1 首版的AI任务

大模型基于后台提供的结构化快照，在合格节点中提出下一站建议，并分别给孩子与工作人员生成简短说明。模型不自行编造实时人数、路径、开放信息或文化史实。

首版使用 DeepSeek 的 `deepseek-flash`，服务地址为 `https://api.deepseek.com`，通过兼容的聊天补全接口调用。密钥仅由服务端读取，保存在项目被 Git 忽略的私有配置中，不进入网页、固件、提交或普通日志。此选择不取消候选校验、八秒时限、明确规则降级及真实请求证据要求。

建议输入包括：已到访节点、已完成关卡、候选节点、节点热度、数据更新时间、节点开放状态、可达关系、可用文化任务。儿童兴趣最多使用“本次完成过哪种任务”这样的可观察偏好，不据此推断年龄、人格或长期画像。

### 15.2 规则与模型的分工

| 阶段 | 执行方 | 要求 |
| --- | --- | --- |
| 计算去重打卡数与趋势 | 后台确定性逻辑 | 结果可复算，不交给大模型数人数 |
| 过滤不可达、关闭和数据失效节点 | 后台规则 | 不合格节点不能进入推荐候选 |
| 综合内容进度与节点情况提出建议 | 大模型 | 必须使用输入候选，不虚构地点 |
| 检查输出字段、地点、时效和约束 | 后台规则 | 校验失败不得直接下发 |
| 展示建议与人工选择 | 终端、手机、可用的腰牌接口 | 建议可拒绝，不自动解锁下一站 |

输出至少包含建议地点、给孩子的一句话、给工作人员的理由，以及所用快照编号。用户界面不展示模型思维过程，工作人员可查看输入统计与最终推荐依据。

示例文案：“下一站去城门找一找藏着的图案吧。”工作人员理由：“城门点近期打卡较少，且该腰牌尚未完成此任务。”这些文本只有在对应数据真实支持时才使用。

### 15.3 模型超时与演示证据

目标响应时间为5秒以内；8秒未返回时，可显示“AI暂不可用”，采用明确标注的规则建议。规则结果与缓存结果不得冒充本次实时AI输出。

验收时保留至少一次真实模型请求的输入快照、返回结果、校验结果和最终显示记录，删除密钥及不必要身份信息。展示不同数据输入下推荐是否相应变化；不为了演示而声称模型每次都应给出不同结果。

AI推荐与硬件反馈构成参赛展示点：扫码事件改变后台信息，推荐影响终端提示；到达被推荐节点后，仍通过实物扫码解锁对应游戏。

## 16. 业务数据与接口边界

### 16.1 核心记录

| 记录 | 关键字段 |
| --- | --- |
| 腰牌 | `badge_id`、展示编号、设备对应关系、状态 |
| 活动会话 | `session_id`、开始时间、结束时间、是否测试 |
| 地点 | `site_id`、名称、地图坐标、可达节点、开放状态、游戏与奖励 |
| 终端 | `terminal_id`、当前地点、配置版本、最后在线时间 |
| 到访事件 | `event_id`、会话、腰牌、终端、地点、采集时间、接收时间、时间质量、来源 |
| 解锁请求 | `command_id`、关联事件、游戏、目标腰牌、创建时间、有效期、执行状态 |
| 游戏进度 | 会话、腰牌、游戏、解锁状态、完成状态、版本、结果来源 |
| 奖励 | 会话、腰牌、奖励、收藏时间、当前展示状态、同步状态 |
| 推荐 | 输入快照、候选、输出地点、说明、模型或规则来源、生成时间 |

`source`至少区分真实场地扫码、实物扫码但模拟地点、后台生成模拟数据。数据集切换必须明确，后台生成的模拟事件不能向真实腰牌发送解锁指令。

### 16.2 待实现的服务接口职责

以下为项目后台的逻辑接口，不是现有吧唧的原生命令。

| 接口职责 | 输入与输出 |
| --- | --- |
| 提交到访 | 接收终端事件，返回事件编号、是否重复、是否可解锁 |
| 获取待处理列表 | 按活动和工作人员权限返回未处理到访 |
| 创建解锁请求 | 校验到访与设备对应关系，返回请求及目标游戏 |
| 上报执行结果 | 区分设备确认、失败、未知及人工核验 |
| 同步游戏与收藏 | 接收设备状态版本，合并不回退的完成记录 |
| 获取地图快照 | 返回各点去重数据、时效与来源 |
| 生成下一站建议 | 接收快照和当前进度，返回校验后的建议 |
| 运行情景推演 | 返回与真实记录隔离的预测曲线及参数 |

到访、解锁、通关、奖励等事件均带唯一编号。设备原接口没有请求编号时，由适配层提供尽可能可靠的去重与回读机制；无法保证的行为写入限制，不宣称已经具备严格幂等性。

## 17. 异常处理与可靠性

| 异常 | 系统行为 | 恢复方式 |
| --- | --- | --- |
| 二维码无法识别 | 提示翻正、靠近或调整光线，不创建到访 | 再次扫码 |
| 未知二维码 | 显示未登记，禁止发送设备指令 | 工作人员检查登记 |
| 相同二维码连续出现 | 合并事件，不重复累加 | 保留首次有效记录 |
| 手机连接了另一枚腰牌 | 显示身份不一致，禁用解锁 | 断开并连接正确设备 |
| 手机断开蓝牙或Wi-Fi | 保留待处理事件，不标成功 | 重连后先查询状态再重试 |
| 后台短暂不可达 | 显示待同步，保留可用本地队列 | 原事件编号补传 |
| 指令超时 | 状态为未确认 | 查询实际状态，避免盲目重复执行 |
| 孩子离开手机范围 | 已解锁游戏和奖励逻辑继续本地运行 | 下次连接同步结果 |
| 腰牌重启 | 读取脚本持久化的活动进度 | 若原运行环境不支持，列为验收未通过项 |
| 通关事件重复 | 更新原进度，不重复发奖 | 返回已完成结果 |
| 图片损坏或不兼容 | 使用预先验证的通用图，保留奖励记录 | 更换资源后重新关联 |
| AI超时或输出错误 | 使用有来源标记的规则建议，或暂不推荐 | 后台重新生成 |
| 地点数据过期 | 地图变灰并标记更新时间 | 终端恢复后刷新 |

原型只保存活动化腰牌记录，不录制儿童面部，不进行身份识别。摄像头用于二维码识别，默认不保存原始视频。真实部署前另行确定告知、数据保留与运营流程，本次不扩展未验证的数据采集。

## 18. 24小时开发范围与安排

### 18.1 必须完成的范围

1. 一枚腰牌、一个活动会话、一套K230和一台安卓手机。
2. K230真实读取背面二维码并记录到访。
3. 手机针对真实事件控制对应实物腰牌。
4. 腰牌运行《秦俑归阵》，通关解锁预置奖励并进入收藏。
5. 七英寸屏展示三节点示意地图和来源明确的打卡热度。
6. 后台完成去重、状态记录和下一站AI建议。
7. 电脑展示趋势与明确标注的情景推演。

不进入本次必须范围：真实景区实时人数统计、精确拥堵预测、无限量游戏下载、修改固件、多个手机并发控制、大规模设备运维、支付与销售系统。

### 18.2 推荐工作分配

按三条工作线分配，人员可兼任，不假定现有团队人数。

| 工作线 | 负责内容 |
| --- | --- |
| 设备与游戏 | 现有接口验证、腰牌游戏、状态保存、通关收藏 |
| 终端与后台 | K230扫码、到访事件、设备对应、去重与状态服务 |
| 界面与展示 | 手机控制、电脑看板、七英寸布局、文化素材与外壳 |

### 18.3 时间表

| 时间 | 主要目标 | 阶段通过标准 |
| --- | --- | --- |
| 0—2小时 | 查明现有脚本环境、控制方式、相机和屏幕是否可用 | 手机上可触发测试内容，K230可读一个二维码；若接口受阻立即上报，不继续堆功能 |
| 2—5小时 | 建立身份对应和最小跨端流程 | 扫码记录到访，手机操作使正确腰牌显示对应测试页 |
| 5—9小时 | 完成秦俑游戏与预置奖励 | 腰牌可实际通关，收藏可查看，重复通关不重复发奖 |
| 9—13小时 | 接入状态确认、去重、断线恢复和七英寸地图 | 手机区分发送与成功，重复扫码不增加窗口去重数 |
| 13—17小时 | 接入真实AI推荐、电脑趋势和情景推演 | 推荐基于真实输入产生，模拟曲线明确标记 |
| 17—20小时 | 修复关键失败、整理外壳与素材 | 关键路径连续完成，操作文字清晰，设备进度能保存 |
| 20—22小时 | 按验收表逐项执行并记录限制 | 未通过项明确，未完成增强项从演示路径移除 |
| 22—24小时 | 演练、录制、整理提交材料和备用内容 | 三分钟演示流畅，资料与真实实现一致 |

外壳测量和打印可与开发同步进行；先以装配和扫码可靠为目标，装饰纹样在结构稳定后处理。基础闭环在第9小时仍未成立时，取消第二、第三个游戏，集中修复设备适配；不通过缩减真实交互来伪造完整度。

## 19. 验收标准

以下全部是计划目标，并非本轮已经测试通过的结果。

| 编号 | 验收内容 | 目标或判定 |
| --- | --- | --- |
| A01 | 初始内容 | 未打卡时只见开场和初始图片，景点游戏无法进入 |
| A02 | 扫码成功 | 固定演示光照和距离下，20次测试至少19次在2秒内完成识别 |
| A03 | 身份对应 | 扫描A后，连接身份不匹配的设备或模拟错误身份时，指令被拒绝 |
| A04 | 重复扫码 | 同一二维码保持入镜不连续累加，网络补传不新增事件 |
| A05 | 手机解锁 | 有效操作后目标5秒内看到腰牌解锁；实际耗时如实记录 |
| A06 | 执行确认 | 未收到设备确认时，不展示自动执行成功 |
| A07 | 拼接游戏 | 三片均正确时才通关，错误选择可恢复，退出不破坏已解锁状态 |
| A08 | 奖励收藏 | 通关自动进入收藏，离开手机通信范围后仍可本地完成与显示 |
| A09 | 进度保存 | 重新打开脚本及按允许方式重启后，解锁和收藏状态保留 |
| A10 | 断线重试 | 至少3次断线重连，不重复发奖、不清空进度、不误解锁其他游戏 |
| A11 | 地图数据 | 手工构造的少量事件与页面去重统计一致；过期数据不会标为低热度 |
| A12 | AI调用 | 至少一次真实模型请求有输入、输出和显示证据；非法地点被校验拦截 |
| A13 | AI降级 | 断网或超时显示规则建议或不可用，不冒充实时AI |
| A14 | 情景推演 | 所有曲线显示单位、参数、数据来源，分流前后人数流向计算一致 |
| A15 | 多节点模拟 | 切换地点不会改写旧事件，界面持续标明演示模式 |
| A16 | 连续展示 | 连续运行30分钟并完成3轮主流程，无阻断性卡死 |

只有一枚实物腰牌时，不能宣称通过“两枚实物设备交叉验证”；可执行身份不匹配的协议测试，并记录验证范围。

## 20. 三分钟现场演示脚本

| 时间 | 演示动作 | 观众应看到的证据 |
| --- | --- | --- |
| 0:00—0:20 | 展示腰牌造型、开场和初始收藏 | 此时没有解锁秦俑游戏 |
| 0:20—0:45 | 将背面二维码对准K230摄像头 | 七英寸屏出现001号到访，手机新增同一条记录 |
| 0:45—1:10 | 工作人员展示手机并点击解锁 | 手机和实物腰牌状态对应，游戏入口真实出现 |
| 1:10—1:45 | 在腰牌完成三片拼接 | 实际触摸、错误可恢复、通关后出现奖励 |
| 1:45—2:05 | 将奖励设为展示，打开收藏册 | 新图进入收藏并可佩戴展示 |
| 2:05—2:35 | 展示地图与下一站AI建议 | 说明热度依据和模型使用的数据，展示真实建议结果 |

备用演示录像记录真实操作，并标注录制时间。现场失败时可以播放录像说明已验证能力，但不能将录像或手机代操作描述成当前实物的即时执行。

## 21. 后续试点与商业验证

优先面向小范围研学活动或单个文化场馆试点，验证儿童是否愿意主动完成任务、工作人员每次操作需要多久、家长是否认可收藏价值，以及推荐是否被采纳。

初步可探索腰牌租赁、腰牌销售与活动内容服务等收入方式，首版不预设售价、复购率或利润。试点记录设备损坏与充电周转、单次接待操作时长、游戏完成率、下一站建议采纳率及用户反馈。

参与腰牌打卡率不足时，运营端结论需限定在参与群体。若要评估真实分流效果，需要独立客流依据和干预前后的可比观察，不能只观察系统自身推荐次数。
