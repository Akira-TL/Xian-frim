# 腰牌只读串口采集边界

## 目的

持续目标要求连续30分钟运行。既有 `scripts/check-device-boot.sh` 会主动复位，不能在连续运行期间重复使用。新增 `scripts/device/observe.sh` 只采集串口，不发送协议命令，不调用复位函数，也不清空已有输入缓冲。

```sh
bash scripts/device/observe.sh --port /dev/ttyACM0 --seconds 15 --log logs/device-passive-new.log
```

日志文件必须为尚不存在的新文件，不覆盖历史证据。默认采集1800秒，最大7200秒；退出成功仅表示采集结束，不判定稳定性、图片或触摸验收通过。启动脚本复用现有 ESP-IDF 的串口环境，不向后台安装硬件依赖。打开串口不等于已证明设备没有复位；控制线实际效果须与实物、蓝牙连接和设备日志交叉核对。

## 实际探测

2026-10-03T08:43:29.211849Z开始，08:43:44.242218Z结束，15秒探测取得8582字节，退出码0。原始日志 `logs/device-qin-ramload-passive-probe.log`，采集过程 `logs/device-qin-ramload-passive-probe-status.log`。

内容包含启动阶段、游戏页面、蓝牙广播、启动时内部内存及至3507毫秒的电量日志；没有取得新鲜的周期运行时间记录。本入口保留了已有输入缓冲，因此不能仅凭这些文字断定采集期间重新启动，也不能断定它们是采集期间的新输出。不能把“没有新增错误”或“进程采集了15秒”当作设备仍连续运行的充分证据。

生产程序有每十秒打印内存的路径，但仅找到路径不证明当前游戏专用运行状态正在执行该路径；本轮未修改固件增加诊断输出或重新烧录。

## 验收影响

本次只证明只读采集入口可以执行，没有开始或通过完整30分钟验收。后续需关联连续手机连接与新的设备认证、实物触摸／画面及可证明设备运行连续性的证据。三次连接、旧认证的后台轮询、宿主绘制测试和启动日志均不能替代三轮完整主流程。
