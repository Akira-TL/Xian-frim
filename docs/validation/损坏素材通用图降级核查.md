# 损坏素材通用图降级核查

2026年10月4日，对应有效PRD第17节“图片损坏或不兼容时使用通用图，保留奖励记录”。

## 当前行为

- 绘制入口先检查尺寸、格式、步幅及数据长度，再使用项目LVGL解码器完整解码；只读素材成功验证一次，失败不永久缓存，以允许后续内存恢复。
- 缺失、不兼容或无法解码的封面、奖励和游戏配图显示原生图形通用纪念章，不依赖另一份图片文件。正常素材保持原图。
- 秦俑碎片沿用各自头、身、腿的原生轮廓，不用三个相同占位图破坏拼图识别。
- 城门图不可用时显示“城门、红旗、大鼓”三个有文字的按钮，不留下不可辨认的透明触摸区域。玩法和阶段规则不变。
- 此路径不调用进度删除或存储修改接口；收藏、展示和复玩仍走已有状态逻辑。恢复素材后，同一奖励重新显示正常图片。

## 已执行证据

执行 `bash scripts/test-qin-render.sh`，日志 `logs/qin-fallback-test.log`：

1. 八份真实素材仍经正式绘制入口产生可见像素，正确槽持续亮边检查通过。
2. 独立损坏输入可执行文件覆盖缺失、不兼容、短数据、坏压缩方式及零尺寸；五个非碎片条目的通用图均改变9992个屏幕缓冲像素。
3. 正常素材与故意损坏素材分别运行同一正式游戏页面，均通过秦俑拖拽、设置返回、左右切换、城门三步、诗句两题、收藏和展示检查。损坏版城门通过实际LVGL指针事件点击文字按钮；设备状态、存储和扬声器接口仍是测试替身。
4. ESP32-S3正式固件构建成功，应用大小 `0x4c5e30`，应用分区剩余20%。日志 `logs/qin-fallback-firmware-build.log`。
5. 本地 `/dev/ttyACM0` 已完整烧录五份映像，各映像摘要校验成功并硬复位；`logs/qin-fallback-flash.log`。未执行整片擦除；本轮尚未取得复位后新的手机认证回读，不用v5回读代替。

故意损坏的头文件只进入两个独立测试可执行文件，不进入正式固件。未向实物烧录损坏资源，也不把帧缓冲检查当作实物触摸、听音或断电保存验收。
