# 吧唧封面传图协议

本功能只替换比赛版游戏入口的封面，不恢复原固件图片浏览器，不修改游戏、进度、收藏、路线推荐或到访记录。

## 图片与存储

手机将图片裁剪为正方形，输出 360×360 的非渐进 JPEG，最大 49152 字节。吧唧使用项目 LVGL 配套的 TJpgDec 完整解码检查尺寸与数据；无法解码、尺寸不符或超过限制的图片不会保存。

16MB 固件新增 `cover` 数据分区，地址 `0xd00000`，大小 `0x20000`。分区分为两个 64KB 存储槽。新图只写非当前槽，校验负载后最后写提交头；原槽不被此次保存擦除。启动时验证两槽，选择有效的最新版本。恢复默认封面也写入新版本记录，因此重启后不会恢复旧照片。无需存储卡，不占用游戏的 NVS 存档。

使用默认公开固件配置，不嵌入私有设备认证密钥。传图特征不要求登记、编号、扫码、配对认证或应用身份授权；浏览器本身要求的设备选择框不能由网页绕过。

## 蓝牙接口

服务 `5e994001-64aa-4a10-b1f1-78ce02b3974f` 下新增可读写特征 `5e994007-64aa-4a10-b1f1-78ce02b3974f`。既有运行状态特征及其版本 2 结构不变。

所有多字节整数使用小端字节序。请求头为 `0x50`、协议版本 `1`、操作码、4 字节非零传输编号，共 7 字节。

| 操作码 | 名称 | 请求头之后的内容 |
| --- | --- | --- |
| 1 | 开始 | 4 字节图片总长度、4 字节 CRC-32 |
| 2 | 数据 | 4 字节偏移、1～180 字节数据 |
| 3 | 保存 | 无 |
| 4 | 取消 | 无 |
| 5 | 恢复默认 | 无 |

数据必须按偏移连续到达。CRC-32 使用反射多项式 `0xedb88320`，初值与最终异或均为 `0xffffffff`；标准检验串 `123456789` 的结果为 `0xcbf43926`。

接收中的连接独占此次传输，但并不认证设备身份。断开时丢弃待保存数据，30 秒没有新数据则超时释放。不同连接不能抢占正在进行的传输。

## 保存结果

读取返回固定 24 字节：

| 偏移 | 内容 |
| --- | --- |
| 0 | 协议版本 1 |
| 1 | 状态码 |
| 2 | 标志：位 0 表示有自定义封面，位 1 表示正在接收 |
| 3 | 保留 0 |
| 4 | 4 字节传输编号 |
| 8 | 4 字节已接收字节数 |
| 12 | 4 字节此次总长度 |
| 16 | 4 字节已保存版本号 |
| 20 | 4 字节允许的图片最大长度；存储不可用时为 0 |

状态码按顺序为：0 空闲、1 接收中、2 已保存、3 请求无效、4 存储不可用、5 忙、6 已取消、7 超时、8 校验不符、9 图片无法解码。

网页必须在提交后读取设备结果，核对状态 2、此次编号以及新的版本号，才能显示成功。传完字节本身不代表保存成功。保存中断不擦除原有效槽；最终确认丢失时，应重新读取状态，不仅根据传输百分比猜测结果。

## 软件验证边界

`bash scripts/test-qin-render.sh` 使用正式 JPEG 解码器、封面绘制函数与 LVGL 屏幕缓冲，检查照片像素确实可见；同时验证 CRC、尺寸和渐进格式拒绝、取消、超时、错误编号、超限、损坏图片、存储失败、重启恢复与恢复默认。闪存接口使用遵循先擦后写规则的内存替身，不触碰实物或用户存档。

此验证不冒充真实手机蓝牙与实物圆屏验收。连接、烧录、重启和其他物理操作由用户负责。
